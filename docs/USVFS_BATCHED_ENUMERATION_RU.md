# Проверка пакетного перечисления каталогов USVFS

Дата: 18 октября 2026 года. Ветка: `codex/usvfs-batched-enumeration`, база CORDON: `388c55a`.

## Результат и решение

Пакетное перечисление ускорило рекурсивный обход синтетического дерева из 10 253
файлов с **1601,60 до 92,37 мс**, примерно в **17,3 раза**, в повторной серии
отдельной сборки после исправления тестов. Это измерение файлового
обхода внутри внедрённого x64-процесса, а не запуска X-Ray, загрузки сохранения или FPS.

**Штатный runtime оставлен прежним.** PR доступен только как дополнительная
экспериментальная сборка через `scripts/Build-UsvfsPr99.ps1`. Три расхождения
собственных тестов разобраны ниже; ограничение асинхронного обхода сохраняется.
Пользователь сообщил об ускорении запуска Anomaly до главного меню примерно
на 10–11 секунд. Это отдельное игровое наблюдение, а не повторяемый замер FPS
или проверка длительной игры и сохранений.

## Что сравнивалось

| Вариант | Ревизия |
|---|---|
| Исходный USVFS, совпадает с manifest лаунчера | `ModOrganizer2/usvfs@57f1ea5e6ad13f7435a7af184748e6c1312c5637` |
| Эксперимент, открытый [PR #99](https://github.com/ModOrganizer2/usvfs/pull/99) | `Illustar0/usvfs@c5f7ef2085bd29a3cca2cd57f3aba84dae030ff5` |

Обе версии собраны из исходников отдельно от `.external/usvfs`, для x64 и x86:
Release, MSVC v143 19.44.35228, Windows SDK 10.0.26100.0, одинаковые установленные
зависимости для соответствующей архитектуры. Машина: Intel Core i5-11400F,
Windows build 26300.9711, .NET SDK 8.0.421.

Для локальной сборки применена существующая поправка `/FIpch.h`.
К тестовым программам обеих версий добавлена системная `delayimp`, необходимая
для `/DELAYLOAD`. У кандидата исключена только отдельная цель Google Benchmark:
пакета нет в локальных зависимостях. Нативные correctness-тесты оставлены включёнными.
Это условия первого сравнения без исправления трёх тестов. Для дополнительной
сборки используется отдельный отслеживаемый патч тестов и их сборки;
алгоритм runtime из PR остаётся исходным.

## Фикстура и методика

Новый [исследовательский бенчмарк](../research/usvfs-directory-benchmark/README.md)
создаёт отдельную фикстуру в локальном Temp:

- 40 включённых модов, по 500 номерных файлов в каждом;
- 1000 номерных файлов базовой игры;
- перекрытия между слоями, общий файл с исключением верхнего провайдера,
  кириллица и отдельный физический файл;
- профильный overwrite; итог — 10 253 файла в `gamedata`.

Правила приоритетов не дублируются: план создаётся через существующие
`FileLayerPlan`, `OverlayManifestBuilder` и `UsvfsMappingPlanBuilder`.
Хост использует настоящий `UsvfsRuntime` и запускает внедрённую копию тестового EXE.

Три пары процессов запускаются в порядке AB, BA, AB. В каждом дочернем процессе
один прогревочный и семь измеряемых обходов `Directory.EnumerateFiles`.
Медиана считается по 21 измерению каждой версии. Файловый кэш прогрет;
во время окончательных замеров другие сборки и тесты не выполнялись.

В таймер входит перечисление с материализацией массива. Сортировка, проверка
имён, чтение выбранных итоговых файлов и операции записи выполняются вне таймера.
Подготовка сеанса измеряется отдельно, без создания процесса и его завершения.

| Метрика | Исходный USVFS | PR #99 |
|---|---:|---:|
| Медиана рекурсивного обхода, 21 измерение | 1395,4576 мс | 80,6652 мс |
| Медиана создания сеанса, 3 измерения | 217,4913 мс | 211,3692 мс |
| Итоговых файлов в каждом обходе | 10 253 | 10 253 |

Существенное ускорение подготовки сеанса по этим трём измерениям не установлено.
Ускорение обхода нельзя переносить на полное время запуска игры.

Повторная A/B-серия выполнена отдельно собранным `Build-UsvfsPr99.ps1` runtime
после исправления тестов, с прежним baseline и тем же компилятором, SDK,
зависимостями и структурой фикстуры. В отличие от первоначального Ninja-build,
дополнительный скрипт использует генератор Visual Studio и временный ASCII-диск.
Порядок AB/BA/AB, 21 измерение обхода каждой версии: **1601,6033 → 92,3701 мс**
(17,34 раза). Создание сеанса: **245,5689 → 260,0564 мс**, по три измерения;
ускорения этой стадии нет. Все проверки состава, overwrite и неизменности
исходных файлов прошли. JSON с замерами и хешами повторной серии:
`research/usvfs-directory-benchmark/obj/comparison-8138d2455ac04adf8d8aaa7be42a2db8/summary.json`.

В каждой серии проверены отсутствие пропусков и дубликатов, содержимое выбранных
провайдеров, fallback исключённого файла, overwrite, физический файл, шаблон
`*.ltx`, создание, атомарная замена и удаление тестового файла. Хост проверяет,
что запись физически попала в overwrite. SHA-256 всех исходных файлов фикстуры
до и после полной серии совпали. Записаны хеши четырёх бинарников каждой версии.
Настоящие папки игры, модов и сохранённые профили не использовались.

## Первоначальные проверки и разбор расхождений

| Проверка | Исходный USVFS | PR #99 |
|---|---|---|
| Нативные наборы x64 | 39/39 | 203/206 |
| Нативные наборы x86 | 39/39 | 203/206 |
| `scripts/Test-UsvfsRuntime.ps1`, по 5 сеансов каждой архитектуры | Прошёл | Прошёл |
| Состав дерева, выбор провайдеров и операции overwrite в бенчмарке | Прошли | Прошли |

Нативные наборы запускались последовательно из отдельного ASCII-каталога Temp.
До исправления тестов на обеих архитектурах кандидата падали:

1. `NtQueryDirectoryFileListsSeveralVirtualEntriesPerQueryLikeNtdll` — при буфере
   312 байт различается количество порций результатов: ожидается 5, получено 4.
2. `NtQueryDirectoryFileListsEntriesOfSeveralSourcesLikeNtdll` — различаются
   заполнение буфера, смещения и распределение записей по вызовам; например,
   `Information` равен 308 вместо 204 байт.
3. `NtQueryDirectoryFileMatchesVirtualEntriesLikeNtdll` — шаблон DOS wildcard `<`
   в нативном обходе включает `.hidden`, в виртуальном обходе кандидата — нет.

Полные последовательности файлов в первых двух случаях совпадают. Контрольный
прогон 96 x64-сценариев охватил 12 классов записей, разные буферы, single-entry,
смену класса, несколько источников, другой регистр и отсутствующие источники.
Пропусков, дублей, неверных смещений и повреждения защитных байтов не обнаружено;
в девяти сценариях различалось только разбиение на порции.

Третье расхождение вызвано коротким именем `HIDDEN~1` у физического `.hidden`:
NTFS сопоставляет шаблон также с этим именем, а виртуальные имена PR не получают
8.3-псевдонимов источника. После удаления короткого имени только у файла новой
тестовой фикстуры совпали все 26 проверенных шаблонов. Политика NTFS и исходные
игровые файлы не менялись.

Патч `scripts/patches/usvfs-pr99-tests.patch` заменяет сравнение порций
сравнением полного упорядоченного списка с проверкой статусов, смещений,
размеров записей, single-entry и завершения обхода. Общий helper запросов
дополнительно проверяет защитные байты после буфера и объявленную длину результата.
В wildcard-фикстуре удаляются автоматически созданные 8.3-псевдонимы только
эталонных тестовых файлов; ошибки удаления завершают тест с ошибкой.

После исправления тестов отдельная сборка прошла **206/206 тестов x64 и 206/206
тестов x86**, без отключённых тестов, и `Test-UsvfsRuntime.ps1` по пять сеансов
каждой архитектуры. XML и журналы итогового прогона:
`C:\Users\itzsy\AppData\Local\Temp\cordon-usvfs-pr99-7bc76d44027248afb610bcd750bb81f0`.
Обработка смены класса записи допускает повтор запроса с большим буфером, если
та же следующая запись больше не помещается. Это проверяется для NTFS и USVFS
независимо, поскольку границы порций различаются.

Патч отдельно применён к чистым файлам закреплённого коммита и воспроизвёл все
три изменённых файла. Проверены отказы сборщика при посторонних отслеживаемых
и неотслеживаемых файлах: исходники сохраняются, автоматического сброса нет.

Есть и заявленное автором изменение совместимости: асинхронные NT-запросы
перечисления с Event/APC и соответствующими handles больше не видят виртуальные
записи. Обычные синхронные обходы нашей фикстуры прошли; использование этих
низкоуровневых сценариев конкретными движками X-Ray здесь не проверялось.

Дополнительно прошли 61 относящийся к USVFS/`FileLayerPlan` тест лаунчера,
Release-сборка, `dotnet format` основной solution и нового research-проекта,
а также проверка whitespace. Общая логика запуска и интерфейсы не менялись.

## Неудачные предварительные прогоны

Первоначальный нативный запуск из пути с кириллицей и затем через `subst`
давал ошибки также у baseline: запуск процессов и нормализация путей.
После переноса тестовых бинарников и fixtures в обычный ASCII-каталог Temp
все baseline-тесты прошли; три ошибки кандидата сохранились.

Первая A/B-серия с фикстурой в OneDrive оборвалась на втором запуске baseline:
`File.Move(..., overwrite: true)` вернул `UnauthorizedAccessException`.
Эта незавершённая серия не включена в итоговые числа. Полная повторная серия
с той же структурой фикстуры в Temp прошла все проверки. Причина первого сбоя
не доказана, поэтому он не приписывается PR или OneDrive.

## Отдельная сборка

После подготовки обычных нативных зависимостей выполните:

```powershell
.\scripts\Build-UsvfsPr99.ps1
```

Нужны Git, CMake, Visual Studio 2022/2026 с MSVC v143 и ASCII-путь TEMP.
Скрипт использует зависимости из `.external/usvfs/vsbuild64/vcpkg_installed`
и `vsbuild32/vcpkg_installed`, а также уже собранные x86 smoke-программы.
При их отсутствии сначала нужен `Build-UsvfsDependencies.ps1`.
Сами исходники PR загружаются отдельно в `.external/usvfs-pr99`; коммит
закреплён, посторонние изменения отслеживаемых исходников отклоняются без сброса.

Скрипт собирает обе архитектуры, запускает шесть нативных наборов каждой
архитектуры в отдельном обычном ASCII-каталоге Temp, затем выполняет
`Test-UsvfsRuntime.ps1` по пять сеансов x64/x86. Четыре итоговых файла
(`usvfs_x64.dll`, `usvfs_x86.dll`, `usvfs_proxy_x64.exe`, `usvfs_proxy_x86.exe`)
копируются в `.external/usvfs-pr99/runtime` только после успешных проверок.
Рядом находится `build-info.json` с коммитом, SHA-256 патча и бинарников и путём
к нативным журналам/XML. Отдельная цель Google Benchmark собирается, если
зависимость установлена; её отсутствие не отключает correctness-тесты.

Для игры четыре файла можно перенести в отдельную копию тестового лаунчера.
Скрипт не меняет `UsvfsRuntimeManifest.psd1`, обычную `.external/usvfs`
и существующие папки `publish`. Собирать пакет или архив он не пытается.

`research/usvfs-directory-benchmark/obj/comparison-ab95c09756ad4a3bab3267ba6121627a/summary.json`.

`.external/usvfs-enumeration/`; `native-test-summary-temp.json` содержит путь к XML.

Перед возможным включением в основной пакет нужны проверки загрузки/записи
сохранений, настроек и длительной игры на используемых x64/x86 движках.
Использование асинхронного перечисления конкретными X-Ray и дополнениями
не установлено; это остаётся ограничением совместимости. FPS, потребление
памяти и производительность x86 здесь не измерялись.
