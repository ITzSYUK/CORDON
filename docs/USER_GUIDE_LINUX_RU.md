## 1. Как это работает

Лаунчер **не изменяет** файлы игры и модов. Для каждого профиля создаётся отдельный каталог:

```
~/.local/share/cordon/profiles/profile-<id>/
├── fsgame.ltx        подготовленная копия файловой карты движка
├── gamedata/         объединённое дерево: данные движка → игра → моды
├── db/, patches/     ссылки на архивы и патчи игры, архивов модов
├── bin/              ссылки на файлы движка
├── _appdata_/        логи, сохранения, скриншоты, шейдерный кэш
└── build-manifest.json   служебный манифест сборки
```

Игра запускается так:

```bash
xr_3da -fsltx <профиль>/fsgame.ltx -overlaypath <профиль>/_appdata_ [-cs]
```

* `-fsltx` — **каталог профиля становится корнем файловой системы движка** (`$fs_root$`).
  Поэтому движок видит моды как часть игры.
* `-overlaypath` — логи, сохранения, скриншоты и `shaders_cache` уходят в `_appdata_` профиля.
  У каждой сборки свои сохранения, они не смешиваются.
* `-cs` — переключатель ресурсов «Чистого неба» (добавляется автоматически).

Порядок слоёв (снизу вверх): данные движка → базовая игра → моды по порядку списка → папка
`overwrite` из Mod Organizer 2. **Чем ниже мод в списке, тем выше его приоритет.**

## 2. Установка

### Скриптом (без root)

```bash
git clone https://github.com/defaultdj/CORDON-LINUX.git
cd CORDON-LINUX
./install.sh                     # в ~/.local
```

> Если клон делался до слияния порта в `main`, обновите его: `git pull`.
> Признак устаревшей копии — нет ни `install.sh`, ни `src/cordon`
> (там только оригинальный Windows-лаунчер).

Появятся `~/.local/bin/cordon` (CLI), `~/.local/bin/cordon-gui` (GUI) и пункт
«CORDON-LINUX» в меню приложений.

Полезные ключи: `--system` (в `/usr/local`), `--prefix DIR`, `--no-gui` (без PySide6),
`--portable DIR`.

### Через pipx / venv

```bash
pipx install "cordon-linux[gui] @ git+https://github.com/defaultdj/CORDON-LINUX.git"
# или из локальной копии (внутри клонированного каталога)
python3 -m venv ~/.venvs/cordon
~/.venvs/cordon/bin/pip install ".[gui]"
```

### Системные утилиты (по желанию)

| Утилита | Для чего | Debian/Ubuntu | Arch | Fedora |
|---|---|---|---|---|
| `fuse-overlayfs`, `fusermount3` | backend «fuse-overlayfs» | `fuse3 fuse-overlayfs` | `fuse3 fuse-overlayfs` | `fuse3 fuse-overlayfs` |
| `7z` | `.7z` архивы | `p7zip-full` | `p7zip` | `p7zip p7zip-plugins` |
| `unrar` | `.rar` архивы | `unrar` | `unrar` | `unrar` |
| `xdg-open` | открытие папок из окна | `xdg-utils` | `xdg-utils` | `xdg-utils` |

Проверить, что нашлось: `cordon tools`.

Обязателен только **Python 3.11+** и **нативная (ELF) сборка OpenXRay**.

## 3. Первые шаги

```bash
cordon tools                                     # что найдено в системе
cordon new "Anomaly 1.5.2" --game ~/games/anomaly   # создать профиль
cordon mod-add "Anomaly 1.5.2" ~/Downloads/Mods     # добавить моды
cordon prepare "Anomaly 1.5.2"                      # собрать оверлей
cordon doctor  "Anomaly 1.5.2"                      # проверки
cordon launch  "Anomaly 1.5.2"                      # играть
```

Или графически: `cordon-gui`. При первом запуске окно предложит создать профиль.

## 4. Окно лаунчера

* **Слева** — список профилей с фильтром. Двойной щелчок по профилю запускает игру.
* **Сверху** — кнопки: «Новый профиль», «Настройки», меню «Профиль», меню «Моды»,
  «Собрать» (F5), «Проверить» (F6), меню «Инструменты» и кнопки **Запустить** (F9) /
  **Остановить**.
* **Вкладка «Моды и приоритет»** — таблица модов: флажок включения, номер, название,
  статус конфликта и путь. Порядок меняется перетаскиванием строк или кнопками «Вверх»/«Вниз».
* **Вкладка «Проверки и конфликты»** — результат проверок: зелёные ОК, жёлтые предупреждения,
  красные ошибки, у каждой — подсказка «что сделать».
* **Вкладка «Диагностика»** — игровой лог, дампы, быстрые кнопки «открыть папку».
* **Вкладка «Вывод игры»** — поток вывода движка в реальном времени (то же, что в
  `logs/cordon-session.log`).

Горячие клавиши: `F9` запуск, `F5` сборка, `F6` проверки, `Ctrl+N` новый профиль,
`Ctrl+E` настройки профиля, `Ctrl+O` добавить моды, `Ctrl+I` установить архив,
`Ctrl+K` конфликты, `Ctrl+R` аудит регистра, `Ctrl+P` отчёт, `Ctrl+,` настройки лаунчера,
`F1` «О программе».

## 5. Профили

**Новый профиль** (или `Ctrl+E` — изменить):

| Поле | Что означает |
|---|---|
| Название | произвольное имя, по нему работают все команды |
| Тип профиля | «Игра + моды» — обычный режим; «Готовая сборка» — запускается как есть, без оверлея |
| Каталог игры | папка с `gamedata/`, `fsgame.ltx` и/или архивами `gamedata.db*` |
| Движок (OpenXRay) | папка с исполняемым файлом; пусто — искать автоматически |
| Данные движка | обычно `/usr/share/openxray`; пусто — определится само |
| Исполняемый файл | путь относительно каталога движка (`bin/xr_3da`) или абсолютный (`/usr/games/xr_3da`) |
| Способ сборки | `ссылки` (по умолчанию), `fuse-overlayfs`, `напрямую` |
| Тип игры | авто/CoP/CS/CoC — определяет ключ `-cs` |
| Данные игры | «внутри профиля» (свои сохранения) или «общая папка игры» |
| Каталог профиля | куда собирать оверлей; пусто — `~/.local/share/cordon/profiles/profile-<id>` |
| Аргументы запуска | дополнительная строка аргументов, например `-nointro` |
| Ключи движка | галочки: `-nosplash`, `-no_gamepad`, `-i`, `-dedicated`, `-gl`, `-savescreenshots`, `-silent_error_mode`, `-nolog` |

Кнопка **Проверить** в диалоге покажет, всё ли на месте, ещё до сохранения.
Кнопка **Найти** автоматически подставит движок и его данные.

Профиль можно **дублировать** (моды копируются, файлы — нет) и **удалить**; при удалении
стирается только каталог профиля и распакованные лаунчером моды, ваши папки с модами остаются.

### Способы сборки

| Backend | Плюсы | Минусы |
|---|---|---|
| **ссылки** | без root, без FUSE, работает на любой ФС, переживает перезагрузку | в каталоге профиля много символических ссылок |
| **fuse-overlayfs** | «честная» файловая система для движка, ничего не копируется | нужен пакет `fuse-overlayfs`, монтирование живёт только во время сессии |
| **напрямую** | мгновенно, ничего не собирается | приоритет модов определяет сам движок; конфликты не разрешаются |

## 6. Моды: добавление и порядок

* **Добавить моды** (`Ctrl+O`) — выбрать папку: лаунчер сам найдёт внутри моды
  (`gamedata/` или разложенные `configs/`, `scripts/`, `textures/`, `db/`). Если выбрать
  каталог с модами, будут найдены все подпапки.
* **Найти моды** (`Ctrl+F`) — показать, что найдено, и добавить по подтверждению.
* Перетаскивание строк или «Вверх»/«Вниз» меняет приоритет.
* Флажок отключает мод, не удаляя его из профиля.
* **Убрать из профиля** — убрать запись (файлы остаются на диске).
* **Удалить файлы** — убрать запись и стереть копию, распакованную лаунчером (ваши папки модов
  не пострадают, удаление вне хранилища лаунчера запрещено).

Кнопки «Включить все» / «Отключить все» — для быстрых экспериментов.

## 7. Установка модов из архивов

**Установить архив** (`Ctrl+I`) или `cordon mod-install "<профиль>" файл1.zip файл2.7z`.

* Поддерживаются `zip`, `7z`, `rar`, `tar`, `tar.gz`/`tgz`, `tar.bz2`/`tbz2`, `tar.xz`/`txz`,
  `tar.zst`.
* Архив распаковывается **в хранилище лаунчера** (`~/.local/share/cordon/mods/profile-<id>/`),
  а не в папку игры.
* Если внутри архива одна корневая папка (`MyMod/gamedata/...`), она «схлопывается».
* Любые попытки выйти за пределы каталога распаковки (`../`, абсолютные пути, симлинки)
  блокируются.
* Файлы `.7z` и `.rar` требуют `7z` / `unrar`; при отсутствии утилиты лаунчер скажет, что
  поставить.

Команды для папок с архивами:

```bash
cordon mod-scan "<профиль>" ~/Downloads/Mods          # посмотреть, что найдено
cordon mod-scan "<профиль>" ~/Downloads/Mods --add    # сразу добавить
```

## 8. Конфликты файлов

**Инструменты → Конфликты** (`Ctrl+K`) или `cordon conflicts "<профиль>"`.

Таблица показывает для каждого мода:

| Статус | Значение |
|---|---|
| Без конфликтов | файлы мода никому не мешают |
| Перекрывает другие | файлы мода заменяют файлы игры/других модов |
| Перекрыт другими | часть файлов мода замещается модами ниже по списку |
| Смешанный | часть файлов побеждает, часть перекрыта |
| Полностью перекрыт | мод не влияет ни на что — можно отключить |

Плюс: количество пересекающихся файлов, список «кто побеждает» по каждому файлу
(`cordon conflicts "<профиль>" --tree`) и подсказка, какие моды можно смело выключить.

## 9. Проверки перед запуском

**Проверить** (`F6`), перед запуском они выполняются автоматически, из консоли — `cordon doctor`.

Что проверяется:

* каталог игры, наличие `gamedata`/архивов/`fsgame.ltx`;
* исполняемый файл движка: ELF (не `.exe`), разрядность, отсутствующие библиотеки (`ldd`);
* доступность выбранного backend и, для fuse, наличие `fuse-overlayfs`;
* доступность папок всех включённых модов;
* целостность уже собранного оверлея (битые ссылки, не примонтированный оверлей);
* права на запись и свободное место (предупреждение ниже 2 ГиБ);
* регистр путей (см. следующий раздел);
* неизвестные ключи командной строки (опечатки в аргументах).

Красные ошибки блокируют запуск (обойти можно только `--skip-check`, для опытных).
Из консоли `cordon doctor --json` отдаёт машинный формат — удобно для скриптов.

## 10. Аудит чувствительности к регистру

Это главная Linux-особенность. В движке на Linux функция `xr_fs_strlwr` — заглушка, поэтому
файловая система **регистрозависима**: мод, который ссылается на `Textures\wall.dds`, а на
диске лежит `textures/wall.dds`, просто «не увидит» текстуру (в игре — чёрные/битые текстуры,
в логе — `cannot find texture`).

**Инструменты → Аудит регистра** (`Ctrl+R`) или:

```bash
cordon audit "<профиль>"        # показать проблемы
cordon audit "<профиль>" --fix  # создать ссылки-алиасы
```

Лаунчер просматривает `.ltx`, `.xml`, `.script`, `.lua`, `.ini`, `.cfg` в оверлее, разрешает
алиасы `$game_data$`, `$game_config$` и подобные, ищет пути, которые на диске отличаются
только регистром, и создаёт рядом символическую ссылку с «правильным» именем
(`gamedata/Textures -> textures`). Сами файлы модов не изменяются.

Найденные алиасы запоминаются в `<профиль>/.cordon-aliases.json` и **восстанавливаются после
каждой пересборки** профиля.

## 11. Запуск игры

Кнопка **Запустить** (F9) или `cordon launch "<профиль>"`.

Что происходит по шагам:

1. собирается оверлей (если состав модов не менялся — сборка переиспользуется);
2. выполняются проверки; при ошибках лаунчер спросит, запускать ли всё равно;
3. движок стартует в каталоге профиля с ключами `-fsltx` и `-overlaypath`;
4. вывод игры пишется в окно и в `<профиль>/logs/cordon-session.log`;
5. после выхода лаунчер считает время сессии, покажет диагностику (лог движка, дампы, если
   были) и отмонтирует fuse-оверлей.

Полезные варианты:

```bash
cordon launch "<профиль>" --dry-run    # только показать команду, ничего не запускать
cordon launch "<профиль>" --force      # пересобрать профиль перед запуском
cordon launch "<профиль>" --detach     # не ждать выхода игры
cordon launch "<профиль>" --skip-check # пропустить проверки
cordon launch "<профиль>" --presence   # статус в Discord (и включён в настройках)
```

**Остановить** (в GUI) корректно завершает движок; несохранённый прогресс, как обычно, теряется.

Чтобы посмотреть, что именно выполнится: `cordon show "<профиль>"` печатает слои, статистику
и итоговый `fsgame.ltx`-путь.

## 12. Сохранения, логи, скриншоты

По умолчанию всё это лежит внутри профиля (`_appdata_`), поэтому сборки не мешают друг другу:

| Что | Путь |
|---|---|
| Сохранения | `<профиль>/_appdata_/savedgames/` |
| Логи движка | `<профиль>/_appdata_/logs/xray_*.log` |
| Скриншоты | `<профиль>/_appdata_/screenshots/` |
| Настройки видео | `<профиль>/_appdata_/user.ltx` |
| Кэш шейдеров | `<профиль>/_appdata_/shaders_cache/` |
| Дампы и крашлисты | `<профиль>/_appdata_/dumps/` |
| Вывод сессии | `<профиль>/logs/cordon-session.log` |
| Журнал лаунчера | `~/.cache/cordon/launcher.log` |

Если нужно общее хранилище, как в обычной установке, выберите в настройках профиля
«Данные игры → Общая папка игры»: тогда `$app_data_root$` будет указывать на папку рядом с
игрой, а профиль перестанет изолировать сохранения.

Быстро открыть нужную папку: `cordon open "<профиль>" root|appdata|mods|logs` или кнопки во
вкладке «Диагностика».

## 13. Импорт из Mod Organizer 2

```bash
cordon import-mo2 "<профиль>" ~/games/modorganizer          # предпросмотр
cordon import-mo2 "<профиль>" ~/games/modorganizer --apply  # применить
```

Лаунчер читает `profiles/<профиль>/modlist.txt`, сохраняет порядок и включённость, переносит
разделители в группы, подключает папку `overwrite` как отдельный слой. Файлы MOD Organizer не
изменяются. Ключ `--modlist-only` применяет только порядок к уже добавленным модам.

В GUI: **Моды → Импорт MO2**.

## 14. Командная строка

```
cordon [--config-dir DIR] [--data-dir DIR] [--cache-dir DIR] [--portable DIR] [--json] [-v] КОМАНДА
```

| Команда | Назначение |
|---|---|
| `list`, `new`, `show`, `edit`, `duplicate`, `delete` | профили |
| `mods`, `mod-add`, `mod-scan`, `mod-install`, `mod-state`, `mod-move`, `mod-remove` | моды |
| `prepare [--force]` | собрать оверлей |
| `launch [--dry-run] [--force] [--detach] [--skip-check] [--presence]` | запуск игры |
| `doctor [--json]` | проверки |
| `conflicts [--tree] [--limit N]` | конфликты |
| `audit [--fix] [--json]` | регистр путей |
| `fsgame [--write]` | показать/записать подготовленный `fsgame.ltx` |
| `import-mo2`, `export`, `import` | обмен профилями |
| `report`, `open`, `unmount`, `tools`, `gui` | сервис |

Примеры:

```bash
cordon edit "Anomaly" --arguments "-nointro -ltx user.ltx"
cordon edit "Anomaly" --backend link --appdata profile
cordon mod-state "Anomaly" "Текстуры HD" off
cordon mod-move "Anomaly" "Оружейный пак" 1
cordon export "Anomaly" ~/anomaly-profile.json
cordon --portable /media/usb/cordon list       # портативный режим
```

## 15. Типичные проблемы

| Симптом | Причина и решение |
|---|---|
| «Исполняемый файл движка не найден» | в настройках профиля укажите каталог движка или абсолютный путь (`/usr/games/xr_3da` для deb-сборки) |
| «Найден Windows-исполняемый файл (.exe)» | это сборка для Windows; нужна нативная Linux-сборка OpenXRay |
| `Exec format error` при запуске | файл движка не ELF либо нет прав: `chmod +x /путь/xr_3da` |
| «Не хватает библиотеки движка» | доустановите зависимости: `ldd /usr/games/xr_3da` покажет список |
| Чёрные/битые текстуры, «cannot find texture» в логе | `cordon audit "<профиль>" --fix` |
| Вылет сразу после заставки | посмотрите `_appdata_/logs/xray_*.log` (вкладка «Диагностика»), часто это несовместимые моды — выключите последние добавленные |
| Мод «полностью перекрыт» | его файлы целиком замещаются модами ниже в списке; можно выключить |
| Игра не видит сохранения | «Данные игры» в настройках профиля: внутри профиля или общая папка игры |
| Оверлей fuse не монтируется | установите `fuse-overlayfs` и `fusermount3`, либо переключитесь на backend «ссылки» |
| Профиль не собирается, «каталог занят» | предыдущее монтирование: `cordon unmount "<профиль>"` |
| Хочу вернуть «чистую» игру | отключите моды или создайте новый профиль: файлы игры лаунчер не меняет |
| Лаунчер не запускается, «нет libGL» | для GUI нужны библиотеки Qt/OpenGL: поставьте `libgl1` (Debian) / `mesa` (Arch) |
| Кончилось место | в статусной строке видно объём профиля; удалите ненужные профили или очистите `~/.cache/cordon` |

Логи для разбора: `~/.cache/cordon/launcher.log` (журнал лаунчера, ротация 1 МиБ) и
`<профиль>/logs/cordon-session.log` (вывод игры целиком).
Отчёт обо всём сразу: **Инструменты → Отчёт** или `cordon report "<профиль>"`.

## 16. Совместимость с движком

| Игра | Поддержка OpenXRay |
|---|---|
| Call of Pripyat 1.6.02 | да (режим по умолчанию) |
| Clear Sky 1.5.10 | да, ключ `-cs` добавляется автоматически |
| Call of Chernobyl / Anomaly | да (определяется как «CoC/Anomaly») |
| Тень Чернобыля (SoC) | нет — OpenXRay её не поддерживает, нужен другой движок |

Установки движка, которые лаунчер понимает:

* системный пакет: `/usr/games/xr_3da`, данные `/usr/share/openxray`;
* portable-сборка: `xr_3da` рядом с игрой или в `bin/`, `bin_x64/`, `engine/`;
* вручную указанный файл.

Ключи движка, которые лаунчер знает (и подсветит опечатки): `-fsltx`, `-overlaypath`, `-ltx`,
`-start`, `-load`, `-dedicated`, `-nosplash`, `-no_gamepad`, `-i`, `-gl`, `-nolog`,
`-savescreenshots`, `-silent_error_mode`, `-cs` и другие — полный список берётся из
bash-completion самого OpenXRay.
